# 老年人版 "AI生活伴侣" — 技术规格

> 版本：v1.0 | 日期：2026-07-25
> 基于：产品迭代实施方案 — 老年人版规格 + Connie确认（4场景+60秒视频+微信消息）
> 状态：MVP已入库（4场景题库+场景匹配器）

---

## 一、产品规格

| 维度 | 规格 |
|------|------|
| 目标用户 | 60-80岁银发族（使用者）+ 子女（代付/推荐者） |
| 诊断形式 | **需求选择模式**（非考试）— 4场景单选 |
| MVP题量 | 4场景（已入库：修照片/防骗/健康查询/语音聊天） |
| 评估方式 | **不评分**，只输出场景匹配度（0-1），推荐最合适的场景 |
| 视频时长 | 60秒，三步可见产出 |
| 交付形态 | 极简H5（大字体24px以上+语音导航）→ 一句话推荐 + 1个60秒教程 |
| 持续推动 | 每3天推送1个新场景（行为触发，非定时） |
| 子女端 | **微信模板消息推送**（Phase1，1周开发）— 不做完整看板 |
| 定价 | ¥99-299/年子女代付 |
| 核心场景 | 女儿发链接「爸，帮我试试这个」→ 选场景→60秒学→发家庭群→女儿点赞 |

## 二、4场景定义

### 2.1 场景对照表

| 编码 | 场景名 | 场景ID | 一句话描述 | 核心痛点 | 社交产出 |
|:----:|:------:|:------:|:----------|:--------|:--------|
| SC-PH-RE-* | 修照片 | photo_restore | 用AI修复老照片 | 有老照片想修复，但不会用工具 | 修复后→发家庭群→获点赞 |
| SC-FR-DE-* | 防骗 | fraud_defense | 识别AI电信诈骗 | 经常接到可疑电话，子女最担心 | 学会后→跟子女说"我会防了"→让子女放心 |
| SC-HE-IN-* | 健康查询 | health_inquiry | AI帮查药品和挂号 | 去药店不懂看说明，怕吃错药 | 查完后→告诉子女"这个药不能和XX一起吃" |
| SC-VO-CH-* | 语音聊天 | voice_chat | 用语音跟AI聊天 | 打字不方便，想试试跟AI说话 | 聊天内容→分享给家庭群→引发讨论 |

```
│                                               │
│  ┌──────────────────┐  ┌──────────────────┐  │

│  每项只需60秒，三步完成                         │
└──────────────────────────────────────────────┘
```

**设计规范**：
- 字体：至少24px，对比度≥4.5:1
- 按钮尺寸：至少64px高度，间距≥16px
- 每个场景：大图标（64px）+ 大字名 + 一行直白说明
- 页面无滚动条，一屏展示完全部选项
- 背景色柔和（#fafafa），主按钮蓝色（#3b82f6）

## 三、60秒视频规范

### 3.1 通用视频模板

```
0:00-0:05 → 标题页："今天学会______，三步完成"
0:05-0:15 → 第一步：屏幕截图指引 + 红圈标记操作位置
0:15-0:35 → 第二步：输入内容 + 大字标注输入框位置
0:35-0:50 → 第三步：点击生成/保存 + 红圈标记按钮
0:50-0:60 → 鼓励页："发到家庭群，让家人看看效果"
```

### 3.2 各场景视频说明

| 场景 | 第一步 | 第二步 | 第三步 |
|:----:|:------|:------|:------|
| 修照片 | 打开AI工具+上传照片 | 输入"把这张照片变清晰" | 点击生成→保存到相册 |
| 防骗 | 打开AI工具 | 输入"这个短信看起来像诈骗吗？" | 截图发给AI→等待判断 |
| 健康查询 | 打开AI工具 | 输入"XX药和XX药能一起吃吗？" | 阅读AI回答→保存截图 |
| 语音聊天 | 打开AI工具 | 点击话筒图标，说"今天天气怎么样" | 听AI回答→后续更多问题 |

### 3.3 视频技术参数

| 参数 | 建议值 |
|:----:|:------:|
| 时长 | 60秒，不超过90秒 |
| 分辨率 | 1080×1920（竖屏） |
| 字幕 | 大字体白底黑字，每个步骤底部居中 |
| 语速 | 慢速（每分钟180字以内） |
| 背景音 | 柔和轻音乐或无背景音 |
| 操作指引 | 红色圆形标记（带脉动动画）圈出关键按钮位置 |

## 四、题库编码方案

```
SC-{场景ID}-{序号}

示例：SC-PH-RE-001 = 场景版/修照片/第1题
```

### 场景匹配逻辑

老年人不走评分器，走`SeniorMatcher`（已入库）：

```typescript
class SeniorMatcher extends Scorer {
  score(input: ScoreInput): ScoreOutput {
    // 1. 用户从4场景中选择1个
    // 2. 记录用户选择了哪个场景
    // 3. 输出：选中的场景 → 推荐场景 → 下次推送间隔
    
    // 匹配度计算：
    // - 用户选A选项（"我想学"）→ matchLevel = 1.0 → 推荐
    // - 用户选B选项（"可以试试"）→ matchLevel = 0.5 → 可选推荐
    // - 用户选C选项（"不需要"）→ matchLevel = 0 → 不推荐
  }
}
```

## 五、推送策略

### 5.1 第一次推送

```
用户完成第一个场景 → 系统自动触发
    ↓
微信模板消息推送给子女：
┌───────────────────────────────────────────┐
│  🎉 您父亲的AI第一课完成！                  │
│                                            │
│  [父亲名]刚刚学会了：                       │
│  ✅ 用AI修了一张老照片                      │
│  [图片：修好的照片]                         │
│                                            │
│  说点什么鼓励他 👉 [回复本条]               │
└───────────────────────────────────────────┘
```

### 5.2 后续推送节奏

```
首次场景完成
    ↓
若2小时内子女未回复 → 系统二次提醒
    ↓
若24小时内子女未回复 → 不推新场景，等子女返回后触发
    ↓
若已回复 → 3天后推送下一个未学场景
    ↓
若已完成全部4场景 → 14天后推送"复习提示"
```

### 5.3 防流失规则

| 场景 | 检测条件 | 动作 |
|:----:|:---------|:-----|
| 首次完成无子女回应 | 2小时 | 系统二次提醒子女 |
| 子女超24h未回应 | 24小时 | 暂停推送，存入等待队列 |
| 用户7天无操作 | 7天 | 子女端触发提醒 |
| 用户完成全部4场景 | 全部完成 | 14天后推复习提示，推荐交叉使用 |

## 七、与儿童版/成人版的架构差异

| 维度 | 成人/儿童 | 老年人 |
|:----:|:---------:|:------:|
| 评估方式 | 评分（0-100） | 场景匹配（0-1） |
| 输出 | 雷达图+分数 | 推荐场景+视频URL |
| 题库格式 | Question[]（多题多维） | Scenario[]（4场景单选） |
| 持久化 | diagnosis_records.result_json | 同（走同一张表，type='senior'） |
| 复测 | 12周后 | 无复测概念（完成场景=毕业） |
| 数据价值 | 能力变化趋势 | 场景完成度、社交反馈数据 |
